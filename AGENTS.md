# AGENTS.md

Audio Notes: upload audio → Gnani transcript → Gemini summary → ask questions. Two independent
apps, no monorepo tooling.

- `backend/` — FastAPI (`app.main:app`), Celery + Redis worker, PostgreSQL, Alembic.
- `frontend/` — Next.js 16 App Router, Tailwind v4, shadcn-style components.

Real entrypoints: `backend/app/main.py` (routes), `backend/app/services.py` (processing pipeline),
`backend/app/agent/` (transcript Q&A agent), `frontend/src/app/` (routes),
`frontend/src/hooks/useNotes.ts` (all server state).

## Setup

- Copy env: `backend/.env.example` → `backend/.env`; `frontend/.env.example` → `frontend/.env`. Never commit `.env`.
- Postgres + Redis: `docker compose up -d db redis`. Postgres is on **host port 5433** (not 5432); Redis 6379.
- Backend venv already exists at `backend/.venv`.
- Frontend env vars: `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_GITHUB_REPO_URL`, `NEXT_PUBLIC_MAX_UPLOAD_MB`.

## Commands (run from the stated directory)

Backend (Windows PowerShell; POSIX equivalent is `.venv/bin/python`):

- Install: `pip install -r requirements.txt`
- Migrate: `.\.venv\Scripts\python.exe -m alembic upgrade head`
- API: `.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload`
- Worker (required for any upload to progress): `.\.venv\Scripts\python.exe -m celery -A app.queue.celery_app worker --loglevel=info --pool=solo`
- All tests: `.\.venv\Scripts\python.exe -m pytest -q`
- One file / one test: `... -m pytest tests/test_agent.py -q` or `... -m pytest -k read_transcript -q`
- Delete recordings + assets (keeps user accounts): `.\.venv\Scripts\python.exe -m scripts.clear_recordings [--status failed]`

Frontend:

- `npm install` · `npm run dev`
- Typecheck: `npx tsc --noEmit`
- **Do not run `npm run build` while `npm run dev` is running.** They share `.next`; the symptom is
  `PageNotFoundError: Cannot find module for page: /...`. Stop dev first.

CI (`.github/workflows/ci.yml`): backend `pytest -q`, frontend `npx tsc --noEmit`. `npm run lint` exists but CI does not run it.

## Verification order

Backend: `pytest -q` needs no external services (in-memory SQLite; external calls are mocked).
Frontend: `npx tsc --noEmit`; only build when dev is stopped. There is no frontend test runner.

## Gotchas (hard-won)

- **Alembic logs to stderr.** Under PowerShell this looks like a failure; verify with `alembic current`
  (should print the head revision), not the exit code.
- `alembic.ini` has a hardcoded URL that is ignored — `migrations/env.py` overrides it with
  `DATABASE_URL` from settings/`.env`.
- Backend startup runs idempotent `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` for every model column
  (Postgres) so dev DBs work without migrating. Still run `alembic upgrade head` (migrations live in
  `backend/migrations/versions/`). SQLite ignores those ALTERs (wrapped in try/except); tests rely on
  `Base.metadata.create_all`.
- Status enums (`ProcessingStatus`, `SummaryStatus`, `ErrorCode` in `app/models.py`) use
  `Enum(native_enum=False)` → stored as strings; add values freely.
- **Restart the Celery worker after backend code changes** — it does not hot-reload. `uvicorn --reload`
  does.
- Gnani: Batch STT with audio ingested by signed URL (`GNANI_CLOUD_INGEST=true`), so no 10 MB byte cap;
  multipart is a fallback. Poll no faster than 10 s. Batch has no ITN; clips ≤ `GNANI_REST_ITN_MAX_SECONDS`
  route to the REST endpoint instead.
- **Gnani returns `speaker_id` even when `with_diarization:false`** (their docs show this). Only keep/show
  speakers when our own `with_diarization` flag is true — see `services._parse_transcript_payload`. Do not
  assume the flag suppresses it.
- Audio is stored in Supabase as a `supabase://bucket/key` ref with a private bucket + short-lived signed
  URLs. Don't reintroduce public object URLs; the frontend appends `?token=` only because `<audio>`/downloads
  can't send an Authorization header.
- **There is no RAG.** Chroma/embeddings and `app/rag/` were removed. Q&A is a tool-using Gemini agent in
  `backend/app/agent/` (tools: `search_transcript`, `read_transcript`, `open_moment`, `list_chapters`,
  `get_summary`, `get_details`). Endpoints `/api/notes/{id}/ask` and `/ask/stream` (SSE). Library search
  (`GET /api/search`) is lexical over segments. Do not add `chromadb`/`langchain` back.

## Frontend conventions

- Tailwind v4 is CSS-first: design tokens live in the `@theme` block of `src/app/globals.css` (mapped to
  the legacy palette). `tailwind.config` does not exist.
- `src/components/ui/*` are hand-authored shadcn-style primitives (not generated by the CLI). Use them.
- Server state is react-query in `src/hooks/useNotes.ts`; `WorkspaceProvider` is UI-only (dialog state +
  a sonner toast bridge). Don't add fetch/polling back into it.
- Legacy `auth.css`/`desk.css`/`architecture/page.css` were deleted; do not re-add handwritten page CSS.

- Explicit image tag: `-Tag <name>`. Default tag is the git SHA — **an uncommitted change reuses the old

- Frontend: `./deploy-frontend.ps1 -ApiUrl https://audionotes.vercel.app -BackendOrigin https://<vm>.sslip.io -Alias audionotes.vercel.app`

- Logs: `gcloud compute ssh audionotes-vm --zone asia-south1-a --command "cd /opt/audionotes && sudo docker compose logs -f --tail=200 api"` (also `worker`, `caddy`, `db`).

Deployment gotchas (learned the hard way):

- Keep `$ErrorActionPreference = "Continue"` in the PowerShell scripts. `"Stop"` turns gcloud's normal
  stderr output into a terminating error; detect failures via `$LASTEXITCODE` instead.
- **Do not pass a multi-line `gcloud compute ssh --command`** — the Windows/gcloud chain splits it on
  newlines. Remote steps live in `deploy/remote-deploy.sh` and are invoked as one line.
- `gcloud builds submit` uploads the source tree; `backend/.gcloudignore` keeps `.venv`/`.env` out.
- New GCP projects do not auto-grant the compute default service account roles. `deploy.ps1` grants it
  `roles/cloudbuild.builds.builder` (to read its source + push) and `roles/artifactregistry.reader`
  (so the VM can pull). Without these, builds fail with `storage.objects.get` denied.
- Vercel enables Deployment Protection (`all_except_custom_domains`) on new projects, which blocks the
  `*.vercel.app` alias. Disable once: `vercel project protection disable audio-notes --sso`.
- **Postgres enforces `VARCHAR(n)`; SQLite does not.** Enum/column-width bugs (e.g. `status` was
  `VARCHAR(11)` while `transcribing` is 12 chars) pass `pytest` and only fail in production. When adding
  enum values, check the migration's column width (and the startup self-heal ALTERs in `app/main.py`).
- Vercel external rewrites have a documented **120 s proxied-request timeout**; large uploads / long SSE
  answers are the cases to watch. Request body size is not capped at the 4.5 MB Functions limit (60 MB
  multipart was verified through the proxy).
